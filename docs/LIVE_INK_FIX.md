# v10：修复落笔期间笔迹不显示

代码检查定位到两条会造成未抬笔笔迹消失的前缓冲交接路径：

1. 隐藏/清屏任务原先在渲染线程真正执行时才取得版本号。新笔已经落下，但旧任务后执行，可能反过来取得更新版本，隐藏新笔迹。`standDown` 的完成回调也未验证自身是否过时。
2. 等待普通画布发布完成后，如果前缓冲此时已经隐藏，延迟启动分支只切换了显示路径，没有马上把这笔已有的采样重绘到新路径。普通画布不再画这笔，而前缓冲要等下一次移动才收到图形。

修复：前缓冲版本号改为调用时同步产生，跨线程原子读取；新落笔、连续书写立即作废旧隐藏、清屏和覆盖任务。回调执行前及回到主线程时均验证版本，活动笔画不能被旧释放任务清除。延迟接管验证笔画身份，并立即重绘已有采样；无限画布同步重建笔画网格。截图覆盖的临时位图使用后释放。

分页笔记与无限画布均应用这些修复。保留 v9 停笔确认、分段、原笔迹编辑等交互，不更换 OCR 模型。

## 验证边界

- 三项确定性单元测试模拟旧隐藏任务晚于新落笔、覆盖/清屏/完成回调过期、正常交接仍能完成的时序。
- Android 截图测试在 DOWN/MOVE 后、UP 之前检查指定笔迹区域的蓝色像素。分页与无限画布各连续 4 笔，包含排入旧图层退场任务后继续落笔。
- 模拟器 SwiftShader 不支持 mutable-render-buffer，截图测试验证的是普通渲染回退路径；真实硬件前缓冲竞态依赖确定性时序测试与代码检查，尚无三星/S Pen 真机复测。不能据此声称所有设备上的现象已完全消失。
- 第一次无限画布截图早于其首帧，测试已改为等待画布实际显示后开始发送笔事件。
