# v4 原始笔迹预览：收益、回退与未通过的质量门

2026-11-12，`0.9.8-latex.4-preview`，versionCode 72。**这不是达标的正式升级。** 原始笔画识别、模型体积和运行耗时有实测改善；学科评分没有获得确认集净收益，纯图片识别则显著回退。因此只发布 prerelease，不替换 v3 正式版；实验学科评分默认关闭。

## 先看完整结果

指标沿用 v3 的保守 MathML 结构匹配：保留符号、大小写、上下标、分式、矩阵、向量和数学字体，忽略部分排版差异。不以可渲染率或候选中出现正确答案代替默认输出正确率；不进行 CAS 求解。全部样本保留在分母内。

| 同一批真实样本 | v3 GLM-OCR | v4 默认输出 |
|---|---:|---:|
| 原 v3 MathWriting excerpt/test 100 条，原始人类笔迹 | 33/100 | **48/100** |
| 原 v3 UniMER-Test HWE 100–199，图片输入 | **56/100** | **1/100** |
| 原来那组混合 200 条 | **89/200** | **49/200** |
| 新专项：100 条高数（极限、积分、微分） | 32/100 | **62/100** |
| 新专项：100 条线代（多列矩阵、行向量） | 28/100 | **54/100** |
| 新专项共 200 条 | 60/200 | **116/200** |

**不能把 116/200 写成原来 89/200 的提升：样本不同。** 上表同时保留原来的两组测试，明确显示图片能力回退。v4 主路径利用白板原始笔画，v3 将这些同源笔画渲染成 PNG 输入 GLM；这是实际应用前后路径的比较，不是统一输入预处理下的模型排行榜。

另冻结了 **240 条此前未参与本轮开发的真实手写**，高数和线代各 120 条。Android 14、2 vCPU、4 GiB 模拟器在飞行模式下运行实际 APK：

| 240 条确认样本 | 默认，实验评分关闭 | 实验学科评分开启 |
|---|---:|---:|
| 高数 | 92/120 | 93/120 |
| 线代 | 109/120 | 108/120 |
| 总计 | **201/240（83.75%）** | **201/240（83.75%）** |

开启评分修正 1 条，同时改错 1 条。新专项 200 条上也是 116→116（1 修正、1 回退）。因此不能宣称学科包已稳定提升准确率，默认关闭其自动评分；包的编辑辅助与独立管理仍可使用。它们确实包含训练统计并参与候选评分，不是把符号按钮称为识别模型，但功能接入不等于效果达标。

240 条的候选集合最多只包含 204 条正确答案，专项 200 条最多 119 条。只重排这四条候选，理论上也不能超过这个上限。后续主要工作应是更强的候选生成、面向真实课堂笔迹的模型适配和独立验证，不能继续用词表数量掩盖识别能力不足。

## 验证过程与数据边界

- 原始来源为 Google MathWriting 2024 的 `human` InkML；逐一核对标签、坐标和原始字节 SHA-256。没有用字体或人工合成字迹充当真实手写。HWE 图片仍用原 v3 固定指纹。
- 学科标签来自冻结的表达式规则，不是人工审核的本科课程试卷。高数组的 `\\frac{d` 规则也会选中普通变量 d 的分式；审计发现专项测试 2 条、原验证 1 条、确认集 4 条需要学科人工复核，均保留在原分母内，没有事后删样提高成绩。线代组主要是多列矩阵、行向量，不能代表全部线性代数题型。
- 原专项验证集 160 条用于模型/解码/重排参数选择。初版自条件候选评分为 140/160，统计重排为 142/160；但第一次专项测试 200 条从 115 降到 114，因此拒绝该配置。
- 最终使用遮盖评分，验证集为 141→142（修正 1、回退 0）。参数固定后再运行新的 240 条确认集；确认结果没有净收益，随后只改变实验选项的默认开关，没有按确认答案调参。
- 240 条取自**官方 valid 分区剩余样本**，不是另一个官方 test 分区；与原验证 160、专项测试 200、v3 excerpt 样本均不重叠，确定性 SHA-256 排序选择。完整选择规则、指纹和失败记录见 [benchmarks/v4](benchmarks/v4/README.md)。不能由此证明上游从未用这些分区选择模型，也不能把结果推广为所有书写者或真实课堂准确率。
- 统计学习只用 229,864 条 HUMAN TRAIN 标签；高数统计涉及 38,842 条，线代 8,859 条。没有用 valid/test 标签更新统计，亦未微调神经网络权重。
- 第一轮 Android 200 条验证输入栅格哈希逐条一致，默认输出与桌面一致。最终 Android 240 条同样逐条像素一致，默认和重排结果均与桌面一致。
- 进一步经过实际 `Stroke` 浮点存储和 `FormulaDraft` 路径：240 条中 19 条栅格有微小变化，全部在 Android 重跑；其余 221 条输入像素完全相同。合并后的生产路径结果仍为 201/240。数据和测试图片只进入测试 APK，不进入应用 APK；用户私有截图没有提交或上传。
- UI 合成交互 fixture 的 `x=1` 被识成 `\chi=1`，这是保留记录的回退，不能算正确。交互测试明确进行人工纠错后再验证插入、拖动、编辑和撤销；没有把手改后的公式冒充自动识别成功。

## 体积、速度与内存

GryphOne 有 29,433,406 个参数；从固定官方 checkpoint 转为两个 Q8 ONNX 图。神经网络权重合计 **32,226,621 B（约 32.2 MB）**，v3 为 1,434,837,056 B。最终 APK **99,917,659 B（约 99.9 MB）**，v3 为 1,492,082,002 B。64 位 arm64-v8a / x86_64，Android 8.0+，与旧 fork 使用同一签名。

在同一个 Android 14、2 vCPU、4 GiB 模拟器，固定同三条公开人类公式（专项清单索引 0、100、199），分别安装实际 v3/v4 APK，关闭网络测量。每条执行冷加载、复用、释放后重载，全部原始结果见 [v3 计时](benchmarks/v4/speed-v3.json) 和 [v4 计时](benchmarks/v4/speed-v4.json)。

| 三条同源公式的平均值 | v3 | v4 |
|---|---:|---:|
| 复用模型总耗时 | 10.254 s | **1.622 s** |
| 已有模型文件，释放后重载 | 11.266 s | **1.781 s** |
| 复用后进程 PSS 快照 | 1671.6 MiB | **397.4 MiB** |

复用场景约减少 84% 耗时。初次从 APK 解包、升级清理旧缓存不作为公平计时比较；PSS 是运行后快照，不是峰值。v3 输入为同源笔画的 PNG，v4 输入为原始坐标，符合各版实际路径。样本仅三条，不是三星 / S Pen 真机的性能承诺，也不能用快但错误的结果证明准确率。

效率措施包括：只绘制选中笔画的中心线，单次图像编码、跨注意力键值共享、20 步四候选批处理；候选不同才追加四步遮盖评分，候选相同时跳过。切换包只做本地重排，不重新识图。单 worker 串行执行，模型闲置 30 秒或内存紧张时释放；取消不提交内容。成功识别后仅清理旧版可重建的 GLM 模型缓存，不删除笔记。

## 发布与使用边界

- [预览 APK 和独立包](https://github.com/Feist-totoo/xnotes-latex/releases/tag/v0.9.8-latex.4-preview) 标为 prerelease，不设为 latest。[v3 正式版](https://github.com/Feist-totoo/xnotes-latex/releases/tag/v0.9.8-latex.3) 保留。
- 面向套索中原始笔画。**图片 OCR 不能用此预览替代 v3**；图像回退的糟糕结果完整披露，不宣传通用识图升级。高数与线代之外的物理学科未做专项准确率验证。
- 高中数学、高数、线代资源随 APK 提供，首次使用不需要网络。其余独立包可主动从 GitHub Releases 下载或本地导入；每包有版本、大小、SHA-256，下载不上传笔迹。预览目录与稳定渠道分开。
- 高数、线代实验评分必须主动开启。其他八个包仍是编辑辅助，不是八个已训练的识别模型。全部候选均需核对，尤其大小写、希腊字母、正负号、上下标与长结构。150 位置的模型不适合一次圈选整页或很长的推导。
- 源代码 AGPL-3.0，GryphOne / ONNX Runtime MIT，DINO Apache-2.0。高数和线代统计资源来自 Google LLC MathWriting，按 **CC BY-NC-SA 4.0** 分发（署名、非商业、相同方式共享）。详见 [使用与许可](FORMULA.md) 和 APK 内 NOTICE。

## 复现

普通构建只需 `python tools/prepare_handwriting_model.py`、`python tools/package_formula_mods.py`，再运行 Gradle；模型下载仅发生在开发机器。完整转换、训练统计与验证流程见 [tools/handwriting](../tools/handwriting/README.md)。指标脚本沿用 `tools/score_formula_structure.py`，没有为了新模型放宽匹配口径。

签名、包内容、JVM/Android 功能检查和发布校验记录在 [release-verification.json](benchmarks/v4/release-verification.json)。准确率失败仍然是失败，不会因功能测试通过而改写为成功。
