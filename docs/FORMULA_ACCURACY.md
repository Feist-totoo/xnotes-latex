# 平板离线手写公式：问题诊断与学科包方案

2026-11-12。约束：所有识别在 Android 平板本机完成；不使用云端或局域网电脑。用户选择的是**学科包**，不是十种硬件规格。

当前版本尚未达到“大部分数学、物理手写式子可靠识别”的要求。本轮修复了确定的排版缺陷，建立了可复现的识别基线；下列十个学科包是待训练、待验证的设计，**不是十个已经可安装、已经提高准确率的模型**。

## 失败原因

截图中的手写意图看起来是 `e^{\arctan(1+x)}`。实际输出包含 `a v c \tan c`，把函数名、括号识别错了。另一个独立问题是 OCR 用空格分隔 token，输出 `e ^ { … }`，而当前排版库把前后两个空格分别当成上标的底和内容；因此源码有上标，预览却展平成正文。

已经通过解析树复现：旧输出得到 `Text(e), Superscript(Space, Space), Group(...)`。修复后得到以 `e` 为底、花括号内容为指数的 `Superscript`。仅规范上下标的无意义分隔空白，保留文字、转义字符和命令边界，不把 `avc` 硬改为 `arc`。

同时拒绝排版器报告的错误和空的上下标参数，防止 `x^2^3` 悄悄显示成 `x^2`。这不等于证明 OCR 语义正确。

## 本次实际测试

数据：公开的 [alephpi/UniMER-Test](https://huggingface.co/datasets/alephpi/UniMER-Test) 的 `hwe` 分割，第 0–99 个样本。样本图片与参考文本哈希见 [hwe-smoke-samples.json](benchmarks/hwe-smoke-samples.json)。样本可能包含照片、噪声和化学式，与白板原生笔迹分布不同。

指标：严格的规范化 token 序列匹配，忽略普通空白、部分显式间距与 `\left`/`\right` 等排版差异，不用 CAS 将不同写法化简为一个答案。它会把部分视觉等价写法计为不匹配，也不是经过人工审核的整式准确率。固定的前 100 个样本仅作诊断，不是随机、按学科和书写者分层的正式测试集。

| 本地诊断配置 | 第一候选匹配 | 前 4 候选包含匹配结果 | 说明 |
|---|---:|---:|---|
| 当前 Texo-transfer ONNX，greedy | 46/100 | — | 当前 Android 模型的桌面参考实现 |
| 同模型，beam=4 | 46/100 | 62/100 | 增加选择机会，没有提高第一候选总数 |
| PP-FormulaNet Plus-S，社区 ONNX | 35/100 | — | 仅作为导出版本的诊断结果 |
| PP-FormulaNet Plus-M，社区 ONNX | 48/100 | — | 增益很小，不能据此决定替换 |

Texo 测试的解码上限为 128 token（应用为 512），100 个 greedy 输出均正常结束，最长 72 token。beam 分支长度惩罚为 0.7。桌面 PIL 与 Android Canvas 插值并不逐像素相同，不能把这些数字直接宣称为 Android 准确率。

PP 模型来自 [GreatV/oar-ocr v0.3.0](https://github.com/GreatV/oar-ocr/releases/tag/v0.3.0)，而非 Paddle 官方直接提供的 Android 包。使用 PaddleX 描述的预处理，核对了官方 S/M 的 tokenizer 词表一致；尚未完成与官方 Paddle 推理逐样本输出对齐，因此这些结果**不能用来断言官方模型排名**。测试模型文件 SHA-256：

- Plus-S：`449d205c8fb2fe0a9b134a5e4a0f2421c2e7812fd902ea67dfda4e9ef4588978`
- Plus-M：`9e3539c2b4eeed28f2d35e342fd5bb0bdaa7f6034a475fc7e890c92780910618`
- tokenizer：`2811d82701ec97c192fa256aa2b4516929373870ae660326cc5b1dc879b95ff2`

用户截图仅在本地裁出原笔迹区域做诊断，没有上传或提交到仓库。该裁图的 Texo 第一候选仍错，正确的 `\arctan` 出现在第 4 候选；Plus-M 也没有正确识别 `arc`。截图压缩图和应用原始笔画并不相同，不能把这个实验当作原始输入的精确复现。

结论：单纯加粗、补边、增加 beam 或换一个更大的通用模型，没有提供足够证据达到目标。需要针对真实笔迹的模型训练与评测，而不是继续堆字符串替换规则。

## 十个可选学科包

通用符号与数字始终可用，学科包可以多选，也可回到通用模式。高等数学包应包含基础函数，不要求重复安装高中数学包。包之间共享底层模型权重，避免十次复制几百 MB 的模型。

| 包 | 重点覆盖 | 必测易错项举例 |
|---|---|---|
| 1. 高中数学 | 代数、函数、三角、数列、解析几何 | `\arctan`、`\log_a x`、根号范围、函数指数、圆锥曲线 |
| 2. 高等数学 | 极限、导数、积分、级数、多元微积分 | 积分上下限、偏导、嵌套分式、`dx` 与乘积、无穷级数 |
| 3. 线性代数 | 矩阵、行列式、向量、特征值 | 矩阵行列对齐、转置、逆矩阵、下标、向量箭头 |
| 4. 概率统计 | 条件概率、分布、期望、估计 | 条件竖线、`\mid` 与绝对值、`\sigma^2`、组合数 |
| 5. 离散数学 | 集合、逻辑、图论、组合 | `\in/\subset`、量词、逻辑箭头、集合与普通花括号 |
| 6. 力学 | 运动学、动力学、功与能、转动 | `v/\nu`、点导数、矢量、角速度、上下标 |
| 7. 电磁学与电路 | 电场磁场、电路、交流、麦克斯韦方程 | `\nabla`、散度/旋度、点乘/叉乘、`\epsilon_0/\mu_0` |
| 8. 热学与统计物理 | 热力学、气体、熵、统计分布 | `\delta Q/dQ`、`\partial`、`k_B`、指数和配分函数 |
| 9. 振动波动与光学 | 简谐振动、波动、干涉、衍射 | `\omega/\varpi`、相位、`\lambda`、复指数与三角函数 |
| 10. 近代与量子物理 | 相对论、量子力学、原子物理 | `\hbar`、bra-ket、算符帽、共轭、张量上下标 |

各包应包含：符号/函数的合法表达及混淆集合、训练数据版本、独立回归集、可选的领域适配权重，以及该版本实测结果。仅有术语表的包应标为“词表辅助”，不能宣传为提高识别精度的专用模型。

## 识别链路的改造顺序

1. **修好排版保真。** 当前已修复空格导致的上下标错误；扩展为学科公式的结构与渲染回归，关注矩阵、cases、算符上下限、向量和量子符号。不能只断言“渲染出了一张非空图片”。
2. **建立真实手写验收集。** 每包至少先收集 200 条、覆盖不同书写者的保留样本，训练/开发/测试按书写者隔离；覆盖干净笔迹、连写、斜写、不同笔宽、长公式及二维结构。用原始 `.xnote` 笔画采样，不只用手机拍照或印刷公式截图。不要把用户纠正过的样本同时用于训练和验收。
3. **选择手写基座。** 继续比较 Texo-distill、UniMERNet-T 等手写相关候选，并完成导出前后的输出对齐；目前没有证据支持把 Plus-M 直接作为“高精度升级”。先保留足够精度，再验证 FP16/INT8 的损失和真机速度。模型文件大小不等于峰值内存。
4. **使用已有的原始笔迹。** 保留每笔的坐标、先后顺序和几何范围，结合图像模型检查候选的分数线、指数区域、上下标、根号范围。最终方向是笔迹与图像联合识别；当前图片 OCR 没有利用这些信息。不能用简单的“上面一行都是指数”规则代替识别。
5. **学科辅助多候选排序。** 保留视觉模型支持的候选，结合当前学科的函数名称和二维结构重新评分。只在独立测试验证净收益后启用自动选择；`a v c \tan` 不能在所有场景一律替换为 `\arctan`。学科信息不能删掉用户写下的不常见变量，也不能把错误公式改成一个“数学上正确”的公式。
6. **局部纠正。** 将不确定区域对应回笔画，优先提供符号/结构候选或局部重写，避免每次修改整行 LaTeX。第一、第二候选有结构冲突时保留手写并提示具体差异；token 概率不能直接标成“97% 正确”。

长期笔迹训练可研究 [Google MathWriting](https://github.com/google-research/google-research/tree/master/mathwriting)。该仓库明确区分代码与数据许可：代码 Apache-2.0，数据 CC BY-NC-SA 4.0；不能将其当作无条件可用于商业分发训练包的数据。此轮未使用该数据训练或分发权重。

## 离线安装与验收

包由本地文件/USB 导入，包含版本、所依赖的基座、权重和词表哈希。识别不增加网络权限，不连接云端或局域网服务；保留已验证包以便回退。可选包界面只有在包确实可用后才显示“已安装”，不放十个实际仍调用同一配置的虚假精度选项。

建议的发布门槛（目标，尚未达到）：各学科的常用单行公式人工审核整式正确率至少 95%，复杂二维公式至少 90%；单独记录正负号、等号、上下标/分式结构的错误率。还需报告首选正确率、候选覆盖率、拒识/超时比例、按书写者结果，以及真机 P50/P95 延迟和峰值内存。复杂长公式不能用简单式子的平均数掩盖。

BLEU、字符正确率、候选里出现正确答案，都不能替代“用户直接接受的第一公式是否完全正确”。[Texo](https://github.com/alephpi/Texo) 还明确说明不同 tokenizer 的序列指标不直接可比；[PaddleOCR 官方表格](https://www.paddleocr.ai/latest/en/version3.x/module_usage/formula_recognition.html) 使用其内部测试集和服务器环境，也不是三星平板课堂手写的整式准确率。

## 可复现工具与当前交付范围

`tools/evaluate_formula_ocr.py` 支持下载并校验上述公开样本，以及完全本地的 greedy / beam=4 / PP-FormulaNet ONNX 诊断。运行方式写在脚本开头。结果默认由调用者保存在 `build/`；用户图片、公开样本图片和模型权重均不提交到 Git。

`0.9.8-latex.2` 是**排版修复版**：增加上标、下标、积分和求和的像素等价回归与错误拒绝检查。OCR 模型未更换，未声称达到上述精度目标。十个学科包、笔迹模型和局部纠正界面仍需后续实现与验收。
